## 一、我们看到的那个"没人做"的位置

知乎最有价值的东西，不是共识，是**分歧**。

同一个问题下面，一位高权威答主说"AI 会取代程序员"，另一位权威度相当、赞同数相当的答主说"不会，代码只是冰山水面上的一角"。这两条回答之间那段张力，才是知乎区别于其他内容平台的核心资产——它让读者意识到"这件事原来有两种同样站得住的判断"。

但今天所有的 AI 产品都在做同一件事：**把分歧总结掉**。

- 输入一个问题，AI 输出一段"综合各方的客观总结"，分歧被抹平成一段四平八稳的废话；
- 推荐系统按兴趣投喂，让你看到更多"你已经认同的观点"——这是信息茧房的经典定义；
- 少数做"观点对照"的产品，也只是把两段文字并排放在一起，读完了事。

**没有人让用户真正站到对立面里去感受一下。**

而我们对"打破信息茧房"的理解是：真正的破茧不是给你看另一方的观点，而是**让你写下回应、核对成立条件，然后发现自己的论证哪里是空的**。这比继续刷总结更接近真实的思考过程。

## 二、产品能力

### 1. 把一场争论拆成阵营（战局）

输入任意争议话题（或从内置样本库选），争鸣会：

- 检索该话题下的站内回答；
- 按 **权威等级^1.5 × log10(赞同数+11)** 加权——权重刻意不用单纯的赞同数，因为"多数人的选择"和"更被认可的判断"不是一回事，而"打破茧房"恰恰需要前者之外的信息；
- 聚成 **2–4 个互斥阵营**，每个阵营给出：阵营名、核心主张、最强 3–4 条论证、立场关键词、加权支持占比、代表人物；
- 用 **分歧烈度**（阵营分布熵 × 权威均衡度）量化这场争论的激烈程度；
- 最后给出 **真正的分歧点** 一句话——不是复述话题，而是点出"双方到底在哪个判断上不一致"。

例如「AI 会取代程序员吗」被拆成：**判断力核心派（38%）／工具赋能派（32%）／需求扩张派（18%）／底层淘汰派（12%）**，真正的分歧点被识别为"「写代码」是否等于「程序员的工作」"。

**每一条论证都挂回它来自哪条回答**（界面上标注 `[来源 N]`），可一键展开原始回答，看到作者、权威等级、赞同数、精选评论和知乎原文链接。

### 2. 回应草稿与回答体检

选择一个观点坐标，写下回应草稿并进行多轮修改：

- 需要回应的不同观点来自已展示、可溯源的知乎快照论据，不是虚构答主发言；
- 界面要求正面回应对方核心主张，避免只做态度表态；
- 你的每一条回应被系统按四个维度打 0–5 分，并给出**一句具体点评 + 一个需要核对的追问**：

| 维度 | 含义 |
|---|---|
| **依据** | 是否落到具体来源、事实、数字，而非空泛表态 |
| **切题** | 是否正面回应对方上一轮的核心主张，而不是自说自话 |
| **逻辑** | 是否有绝对化、诉诸情绪、偷换概念；有因果链条与限定条件得分更高 |
| **增量** | 是否带来了新信息，而不是复述已有立场 |

- 支持**一键换边**：同一段话站在另一边说，体验完全不同的压力——这是最直观的"破茧"时刻。
- 可切换观点坐标：同一份回应换到另一侧后重新体检，观察结论依赖了哪些前提。

### 3. 观点体检报告

对练结束生成可带走的报告：

- **四维雷达画像**：你在哪一项上最强、哪一项最该补，并给出具体的改进动作；
- **你可能低估的那一方**：按加权支持度找出你立场之外最被认可、但你大概率没认真读过的一方；
- **可继续阅读的相反立场作者**：从对立阵营里按权威度 × 赞同数推荐作者，点击可回到原文核对；不暗示已建立私信或真人社交关系。
- **社区复核链接**：报告页生成仅含话题快照 ID 的分享链接，邀请朋友打开同一张分歧地图共同复核。
- **分享海报**：一键导出 PNG，可直接发到知乎想法或项目广场。

## 三、技术实现方案

### 架构

```
web/            纯静态前端（零第三方依赖，无构建步骤）
  config.js     运行模式探测 + 三级降级判定
  providers.js  知乎开放平台客户端 + 快照库 + 结果缓存
  llm.js        模型调用（后端 / 自带 Key），含 JSON 宽容解析
  pipeline.js   立场聚类 · 辩论回合 · 体检报告
  views/        首页 / 战局 / 对练 / 报告与海报
server/index.mjs  可选后端：转发知乎与模型请求，接口白名单 + 单 IP 限流
tools/          构建期管线：采集 → 聚类 → 体检
```

前端刻意不使用任何框架和构建工具：静态托管即部署，评委打开链接的第一秒就能用，不依赖任何 CDN。

### 三级降级：Demo 一定跑得起来

评审现场可能没有密钥、可能模型额度用尽。所以每条能力都有可解释的降级路径，且界面**如实标注**当前处于哪一层，不假装自己有模型：

| 层级 | 数据 | 立场分析 | 回应体检 |
|---|---|---|---|
| 完整 | 开放平台实时 | 模型聚类 | 模型四维裁判 |
| 自带 Key | 开放平台实时 | 模型聚类 | 模型裁判 |
| **默认（公网 Demo）** | 内置知乎公开问答离线快照 | 构建期分歧结果 | 可解释规则引擎 |

**本地回答体检不是占位符**：它用四个可核验信号打分——引据数量（正则识别《标题》/数字/百分比）、与回应对象观点的 2-gram 重合度、绝对化与情绪词计数、本次回应的新词比例；回应提示直接取自已聚类好的真实阵营论据。实测同一段发言在模型裁判下得 13/20（依据 2、切题 3、逻辑 4、增量 4），在本地裁判下得 15/20（依据 4、切题 2、逻辑 4、增量 5），两者都准确指出了"依据不足"这个真正的短板。

### 数据可信性（这条被写成了强制校验）

作品里出现的每一段回答摘要、作者、赞同数、评论数与原文链接都来自知乎真实内容，立场聚类是构建期计算结果。`tools/validate-dataset.mjs` 会在构建和 CI 中强制校验，不满足就直接失败：

- 每一条回答都必须被某个阵营认领（不允许"分析漏了人"）；
- 每一条论证都必须给出 `evidenceIds`，且必须落在本阵营内（不允许张冠李戴）；
- 每一条回答必须带可访问的知乎原文链接（不允许无出处的论断）。

当前状态：**话题 6 个 · 回答 42 条 · 作者 34 位 · 全部通过体检**。

聚类本身也做了防御：模型必须把**每一条**回答归入某个阵营，模型漏掉的回答会按关键词相似度补位；`support` 由真实权重算出而不是采信模型自报的数字；引用了不属于本阵营回答的论证会被直接丢弃。这样"可溯源"不是一句口号，而是被代码保证的性质。

### 开放平台能力的使用

| 接口 | 争鸣用它做什么 |
|---|---|
| 知乎搜索 | 拉取话题下的回答，`AuthorityLevel` 作为立场权重与可信度信号 |
| 热榜 | 提供"当前社区真实焦点"入口 |
| 全网搜索 | 站内样本不足时补充外部视角 |
| 关注流 / 关注列表 | 立场互补答主推荐的真实关系基础 |
| 直答 Agent | 可替换为裁判模型档位 |

**额度保护**：搜索结果按 URL 做 10 分钟本地缓存；后端对单 IP 限流；构建期把聚类结果固化成快照——同一个话题反复被打开时不再消耗任何调用量。这对热榜 100 次/天、直答 100 次/天的限制是必要的工程设计。

## 四、与知乎社区生态的契合度与场景价值

**为什么这件事应该由知乎做、也只有在知乎能做**：

1. **数据独占性**。立场聚类需要"同一问题下的多条高权威回答 + 权威等级 + 赞同结构"。这个语料结构是知乎独有的，任何外部产品都拿不到——不是模型能力的差距，是数据结构的差距。
2. **反向强化社区价值**。争鸣不生产内容、不与创作者争夺流量，它做的是**导流回原文**：每一条论证、每一位推荐答主都直接链回知乎。用户越用它，越会去读原作、关注作者、参与原问题下的讨论——这是对创作者的正向激励。
3. **供给侧价值**。破茧会让用户从"只看认同的内容"转向"主动找对立面"，这会提高评论区和回答区的讨论质量（提高"内容质量"，正是评审维度里明确提到的一点）。
4. **校园与职场场景天然契合**。考研、生化环材、大厂 vs 考公、天赋与努力、AI 会不会取代程序员——这些话题正是学生和职场新人真实纠结的问题。内置样本库首批 6 个话题全部选在此类议题上，而不是猎奇话题。

**落到具体场景**：学生准备保研面试/求职面试前，可以用争鸣把"这个观点会被怎么反驳"过一遍；职场新人在做职业选择时，能看到两种同样站得住的判断各自依赖什么前提，而不是被单一叙事带着走。

## 五、创新点小结

1. **把"分歧"当作一等公民**。不是又一个把争论收敛成结论的 AI 产品，而是把分歧结构化、可视化、可交互。这是与现有 AI 摘要/问答类产品最本质的区别。
2. **"回答体检"而非"观点总结"**。用户不是只读摘要，而是要写回应、查证据、补条件。四维裁判把"这句话哪里站不住"变成具体、可改进的反馈。
3. **权威度加权的立场度量**。用`权威等级^1.5 × log(赞同)`而不是单纯赞同数，让"支持度"反映的是被认可的判断，而非声量——这直接服务于"打破信息茧房"的目标。
4. **可溯源的论证链与强制校验**。把"不杜撰、可溯源"从提示词里的请求升级为构建期会失败的硬约束。
5. **诚实的降级设计**。没有模型就说没有模型，界面明确标注运行姿态，绝不用预设话术假装 AI 在思考。

## 六、完成度与后续规划

**当前已完成并可公网体验**：首页与离线快照库、问题分歧地图（立场拆解 + 溯源抽屉）、回应草稿（多轮提交 + 四维体检 + 观点坐标切换）、体检报告（雷达 + 洞察 + 作者推荐）、分享海报导出、运行模式设置面板、可选后端与限流、数据体检脚本与 CI。

**拿到开放平台凭证后的下一步**：

1. 用 `tools/fetch-answers.mjs` 把样本库从页面采集切换为官方接口检索，覆盖量显著提升；
2. 接入 `X-OAuth-Token`：用户授权后基于**自己的收藏夹与关注关系**做立场分析——"你的收藏里 80% 是同一立场"，这将是"观点体检报告"里最有冲击力的一栏；
3. 把"发现与自己观点互补的知乎用户"做成真正的连接功能——这是灵魂匹配局的终点：不是按兴趣匹配同好，而是**按立场互补匹配能让你想清楚的人**；
4. 用直答 Agent 的不同档位做裁判模型分层（快速档做初判、深度思考档做争议回合）。

## 基于同届项目观察的定位校准（2026-09-12）

官方赛道原文将「灵魂匹配局」定义为：从知友的兴趣、观点和内容行为出发，设计同好发现、讨论参与和关系建立；同时鼓励内容驱动的兴趣匹配、表达助手，以及人与 Agent/Agent 与 Agent 的社区互动（官方说明：https://zhuanlan.zhihu.com/p/2072692085925177157）。圈子近期项目中，已有多款明显偏游戏化（真假 Agent 问答、3D 词云、互动探案）、知识整理（知树、收藏星空）和内容评审（刘看山推荐）。

因此争鸣不应改造成另一款 AI 辩论游戏；差异化应保持「问题分歧地图 + 回答体检」，但必须把**连接动作**从口号变成闭环：

- **保留（主线）**：离线快照、分歧地图、成立条件、原回答溯源、四维体检、换边/替对方辩。它们同时服务知识质量与社区讨论，且避开已有游戏项目同质化。
- **删减（叙事）**：弱化“战局/对抗/裁判”等游戏化词汇，避免把产品讲成 AI 辩论；不承诺“实时知乎 API”，默认姿态继续标注离线快照 + 本地规则裁判。
- **新增（连接最小闭环）**：在报告页增加“找一位观点互补的知友”卡片：展示 2–3 位来源可追溯答主、其代表分歧点和原文链接；提供“带着一个具体追问去原回答评论区”按钮（仅跳转，不代发）；允许用户复制带引用的讨论邀请文本，与队友/朋友共同复核同一分歧点；记录“已读对立观点/已回应”状态，形成可见讨论路径。
- **评审可见性**：3 分钟演示必须在前 40 秒展示一个真实用户问题、两方成立条件和答主卡片，随后演示写回应→体检→一键带着追问回到原文。评委应看到“发现人—理解分歧—产生回应—回到社区”的连接链，而非只看到评分仪表盘。

官方赛事文章给出的时间线为 8 月 15 日—9 月 13 日报名组队、9 月 13 日—15 日 48 小时开发、9 月 15 日—17 日评审、9 月 19 日决赛路演；均应以官方最新通知为准。官方评审权重未在当前可见页面明确，文档中不得自行写死比例。
