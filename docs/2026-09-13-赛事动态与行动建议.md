## 对争鸣的判断

竞品继续加码“视觉世界 / 游戏 / 收藏整理”。争鸣不应跟进做 3D、剧情或 Agent 博弈，而应守住更有差异的链路：

> 高赞回答为何冲突 → 各自成立条件 → 用户写回应 → 四维体检 → 证据引用与朋友复核。

这条链路与“社区连接与兴趣社交”仍匹配：连接不是虚构聊天，而是让同一问题上的不同观点、原作者与朋友复核发生真实的下一步。

## 今日优先级

### P0：必须由参赛账号完成

1. 登录 [官方 Hackathon 页面](https://www.zhihu.com/hackathon)，确认报名状态、项目提交入口、是否要求 AI Works 项目链接、当前截止时间与必填材料。
2. 若项目入口开放，立即提交或保存“争鸣”的作品草稿：名称、赛道、体验链接、仓库链接、计划书和视频链接。不要等待更多功能。
3. 在圈子/想法发布一条短说明，邀请用户留下“看完高赞回答反而更纠结”的真实问题；这是为样本库收集真实问题，也能验证产品需求。

### P1：今晚可完成

1. 录制 60–90 秒竖屏/横屏短演示：首页 → AI 程序员快照 → 展开原回答 → 选择观点 → 提交回应 → 体检 → 复制引用/邀请朋友复核。
2. 用 Demo 导出的海报配合短文发布，文案避免“AI 替你辩论”，强调“回答很多，但大家究竟在哪个条件上不同”。
3. 选 2–3 个来自评论区的真实问题，作为下次快照扩展候选；先保留原链接、作者、回答 ID 和短摘录，再进入构建。

### P2：仅在官方要求 AI Works 链接时

按官方 Skill 在隔离副本中执行 **只读探测**。当前仓库曾因 `web/data/topics/*.json` 命中静态树安全门禁，不能绕过该门禁或把 GitHub Pages 误写为 AI Works 部署；先得到官方可接受的交付路径再构建。

## 建议的发布标题

**当高赞回答彼此冲突，我们到底该相信哪一条？我做了一个知乎问题分歧地图。**

一句话简介：

> 争鸣不替你生成第 N 个答案；它把知乎同一问题下的不同回答、成立条件和原文来源并排放好，让你写一次回应并做四维体检。
