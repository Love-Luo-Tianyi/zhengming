# 争鸣｜知乎问题脉络与观点对练

> 知乎黑客松 2026 · 校园新锐季 ｜ 赛道：**灵魂匹配局（社区 × 社交）**

争鸣不是 AI 辩论游戏，也不模拟真实答主。它把知乎公开问答整理为**问题分歧地图**，让用户写回应草稿，再做**依据 / 切题 / 逻辑 / 增量**四维回答体检，并回到原回答溯源：

1. **把一场争论拆成阵营** — 输入一个争议话题，争鸣按权威等级 × 赞同数加权，把站内回答聚成 2–4 个互相排斥的立场阵营，每个阵营给出核心主张、最强论证，并**把每条论证挂回它来自哪条回答**。
2. **写回应并体检** — 选择观点坐标，提交你的回应草稿。系统以已展示的对立论据为参照，按 **依据 / 切题 / 逻辑 / 增量** 四个维度给出本地可解释评分与修改提示。
3. **带走一份观点体检报告** — 四维雷达画像、你可能低估的那一方、立场互补的答主推荐，以及一张可下载的分享海报。

**它和"总结共识"类产品的区别：争鸣不告诉你答案，它让你看清对面最强的那一击长什么样。**

## 快速开始

```bash
# 方式一：纯静态（零依赖，离线可用）
npx serve web          # 或任意静态服务器指向 web/ 目录

# 方式二：带后端（推荐，密钥留在服务端）
node server/index.mjs  # 默认 http://localhost:8787
```

打开页面即用：内置 6 个知乎公开问答离线快照，无需任何密钥即可跑通全流程。默认不调用实时知乎 API。

> **重要边界**：本项目为独立、非官方演示；默认数据是离线快照，默认裁判是本地规则引擎，不代表实时知乎内容、知乎官方立场或真实答主。

### 可选外部能力（待官方复核）

| 想开启 | 做什么 |
|---|---|

## 三级降级：为什么这个 Demo 一定跑得起来

评委打开链接的那一秒，可能没有知乎密钥、可能没有模型额度。所以争鸣的每一条能力都有可解释的降级路径：

| 层级 | 数据 | 立场分析 | 回答体检 |
|---|---|---|---|
| **完整** | 知乎开放平台实时 | 模型聚类（按权威度加权） | 模型四维裁判 |
| **自带 Key** | 开放平台实时（密钥存本地） | 模型聚类 | 模型裁判 |
| **默认公网 Demo** | 内置知乎公开问答离线快照 | 构建期结果 | 可解释规则引擎 |

**本地体检不是占位符**：它用「引据数量、与回应对象观点的 2-gram 重合度、绝对化/情绪词、新词比例」四项可核验信号打分，反馈直接取自已聚类好的真实阵营论据。降级时界面会明确标注当前处于哪一层，不假装自己有模型。

## 工程结构

官方赛事与 AI Works Skill 的核对记录见 [`docs/官方要求与Skill核验.md`](docs/官方要求与Skill核验.md)；该文档区分 GitHub Pages 演示与待官方复核的 AI Works 交付路径。

```
web/                     纯静态前端，无构建步骤，可直接托管
  js/config.js           运行模式探测与三级降级判定
  js/providers.js        知乎开放平台客户端 + 快照库 + 缓存（保护日额度）
  js/llm.js              模型调用（后端 / 自带 Key），含 JSON 宽容解析
  js/pipeline.js         立场聚类 · 辩论回合 · 体检报告（模型版 + 规则版）
  js/dom.js              DOM 与格式化工具（零第三方依赖）
  js/views/              首页 / 战局 / 对练 / 报告与海报
  data/topics/           样本库：话题快照 + 构建期分析结果
server/index.mjs         可选后端：转发知乎与模型请求，密钥不出服务端，带限流
tools/build-dataset.mjs  构建期管线：采集结果 → 立场聚类 → 快照
tools/validate-dataset.mjs 数据体检：归属完整性、论证可溯源性、回答 ID、摘录长度与链接一致性
```

## 数据可信性

作品里出现的每一段回答摘要、作者、赞同数、评论数和原文链接都来自**知乎公开问答页面**，立场聚类是构建期计算结果。这一点由 `tools/validate-dataset.mjs` 强制校验，不满足就构建失败：

- 每一条回答都必须被某个阵营认领（不允许"分析漏了人"）
- 每一条论证都必须给出 `evidenceIds`，且必须落在本阵营内（不允许张冠李戴）
- 每一条回答必须带作者、真实回答 ID、可访问的知乎原文链接（不允许无出处的论断）
- 摘录限制为短摘录，避免转载式展示；完整内容请以原文为准

```bash
node tools/validate-dataset.mjs
# 话题 6 个 · 回答 42 条 · 作者 34 位
# ✓ 全部快照通过体检：回答归属完整、论证均可溯源、链接均为知乎原文。
```

## 可选开放平台能力（待官方复核）

| 接口 | 争鸣用它做什么 |
|---|---|
| 知乎搜索 | 拉取话题下的回答，`AuthorityLevel` 作为立场权重与可信度信号 |
| 热榜 | 提供"当前社区真实焦点"入口 |
| 全网搜索 | 站内样本不足时补充外部视角 |
| 关注流 / 关注列表 | 立场互补答主推荐的真实关系基础 |
| 直答 Agent | 可替换为裁判模型档位 |

**额度保护**：搜索结果按 URL 做 10 分钟本地缓存，避免同一话题反复消耗日调用上限（热榜 100/天、搜索 1000/天、直答 100/天）。

## 隐私边界

- Access Secret 与模型 Key 只写入浏览器 `localStorage`，或留在服务端环境变量；
- 前端**从不**把密钥写进代码、URL 或日志；
- 后端只放行必要的知乎接口，并做单 IP 限流。

## 已知限制

- 未登录状态下的知乎公开页面只暴露部分回答，因此内置快照的样本量有限；接入开放平台后覆盖会显著提升。
- 快照的「权威等级」由站内可核验信号（认证标识、粉丝量、赞同数）映射到 1–4 级；接入开放平台后直接使用官方 `AuthorityLevel`。
- 本地规则裁判能稳定给出可解释评分，但只有模型裁判才能理解论证的微妙之处——这也是我们鼓励接入模型的原因。
